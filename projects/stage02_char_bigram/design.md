# 02 字符 bigram 设计报告

## 1. 项目目标

本项目用一个最小的字符级语言模型，完整观察“文本 → 相邻字符关系 → 下一字符概率 → 序列输出”的过程。

重点不是生成高质量文本，而是理解词表、条件概率、计数平滑、交叉熵、困惑度、采样以及模型保存和加载。

## 2. 要解决的问题

给定当前字符，预测下一个字符的概率分布：

```text
c_t → P(c_{t+1} | c_t)
```

模型单次输入一个字符。生成功能从一个起始字符开始，重复调用这个预测关系，输出一段字符序列。

## 3. 数据设计

项目保留两种用途不同的语料：`DEFAULT_CORPUS` 是重复短文本构成的教学基线，用于保持历史结果可复现；`REAL_CORPUS` 是美国《独立宣言》的公共领域节选，保留自然文本中的大小写和标点，不使用重复扩充。词表由本次所选语料中出现过的不同字符构成，并按字符排序以保证 ID 稳定。

两种语料使用完全相同的切分、拟合、评估和采样逻辑，因此差异来自语料规模与字符转移分布，而不是两套模型实现。默认训练继续使用基线语料，真实语料作为独立对照，不覆盖原运行结果。

长度为 `n` 的文本会产生 `n-1` 个相邻字符对。例如：

```text
文本：small
输入：s  m  a  l
目标：m  a  l  l
```

训练、验证和测试采用顺序切分 `80%/10%/10%`。模型只用训练部分统计概率；验证和测试部分只用于评估。

## 4. 模型设计

### 4.1 词表和 ID

字符不能直接作为矩阵索引，因此使用：

```python
to_id = {ch: i for i, ch in enumerate(vocab)}
```

如果词表大小为 `V`，每个字符会对应 `0` 到 `V-1` 的整数 ID。

### 4.2 bigram 计数矩阵

`counts[i, j]` 表示 ID 为 `i` 的当前字符后面出现 ID 为 `j` 的字符的次数。

```text
行：当前字符
列：下一个字符
```

### 4.3 条件概率矩阵

每一行归一化得到：

\[
P(j|i)=\frac{count(i,j)}{\sum_k count(i,k)}
\]

因此 `probs[i]` 就是当前字符为 `i` 时的下一个字符概率分布。

### 4.4 计数平滑

初始化计数矩阵时为每个转移加入 `smoothing=1e-3`。这样没有在训练语料中出现的转移仍有极小概率，不会产生 `log(0)`。

## 5. 训练和损失

当前模型没有需要通过梯度反复更新的参数。概率表可以由计数直接得到，因此 `fit()` 是最大似然计数估计，不使用反向传播或梯度下降。

对每个真实相邻对 `(c_t, c_{t+1})`，交叉熵损失为：

\[
L_t=-\log P(c_{t+1}|c_t)
\]

整段文本的 loss 是所有相邻对损失的平均值：

\[
L= -\frac{1}{n-1}\sum_t \log P(c_{t+1}|c_t)
\]

困惑度定义为：

\[
PPL=e^L
\]

## 6. 推理和生成

生成时使用概率行进行随机采样：

```text
起始字符
  ↓
查询 P(next | current)
  ↓
按概率采样下一个字符
  ↓
重复
```

`seed` 用于保证采样结果可复现。生成阶段从保存的 `npz` 文件加载词表、计数和概率，不重新训练。

## 7. 模型生命周期

```text
train.py：构建词表 → 统计训练集 → 评估 → 保存模型
generate.py：加载模型 → 输入起始字符 → 采样输出
tests：独立构造模型 → 验证统计、评估、采样、保存加载
```

推理模型文件只保存词表和概率矩阵。加载时根据词表重建 `to_id`，直接恢复 `probs`，不再从训练计数重新计算概率。`counts` 只存在于训练内存中；如果加载后的模型再次调用 `fit()`，会重新创建计数矩阵并从新语料开始统计。

## 8. 主线文件

- `data.py`：语料和顺序切分
- `model.py`：词表、计数、概率、loss、困惑度、采样、保存和加载
- `train.py`：训练、评估和保存模型
- `generate.py`：加载模型并生成文本
- `tests/test_char_bigram.py`：模型行为和持久化测试

## 9. 设计边界

- bigram 只使用一个字符的上下文，不理解更长的词或句子语义。
- 当前词表来自固定语料，词表外字符会被拒绝，没有 `<UNK>` 机制。
- 顺序切分适合当前教学语料，不等同于严格的独立同分布数据划分。
- 计数平滑只避免零概率，不会让未见过的字符转移获得可靠语义。
- 当前实现是教学用 NumPy 代码，不代表生产语言模型的质量或能力。

## 10. 原始采样与改进采样

项目同时保留两种采样方法：`sample()` 是对完整词表按原始概率采样的基线；`sample_new()` 先进行 temperature 调整，再保留 top-k 候选并重新归一化。两者共享同一张概率表，区别只在推理阶段的采样策略。
