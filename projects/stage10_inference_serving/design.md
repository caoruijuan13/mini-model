# 10 设计：模型评估与推理运行时

## 核心逻辑和主要功能

阶段 08 的自回归模型接收形状为 `(B, T)` 的字符 token ID，输出 `(B, T, V)` 的下一 token logits。阶段 10 复用该模型，不重新训练参数。运行时负责加载绑定的模型和 tokenizer，随后将输入文本编码、执行推理、把生成 ID 解码为文本，并记录调用行为。当前已实现加载、单条、顺序批量、流式生成、perplexity 评估、本地命令行接口和性能报告。

## 输入输出与边界

- 当前输入：`InferenceRuntime.load(path)` 接收阶段 08 的自包含 `.pt` 推理文件路径；输出持有已加载模型与 tokenizer 的运行时对象。
- 推理文件包含格式名、版本、模型配置、权重和完整字符词表；阶段 08 的两个加载入口共享同一套外层格式检查，并分别报告格式、版本、缺失词表和词表大小错误。
- 单条推理接收文本提示、生成长度和采样配置，返回原始输入、新增文本与终止原因。顺序批量推理对每条输入调用单条方法，seed 按输入序号递增；这不是一次张量批处理。
- 流式生成逐次输出新增片段；同配置和随机种子下，片段拼接等于非流式新增文本，EOS 结束迭代且不作为文本输出。
- 固定的训练、验证、测试文本沿用阶段 08 的顺序切分。测试集只用于已选定模型的最终评估；perplexity 基于 token 目标的平均负对数似然，人工生成质量另行观察，二者不能互代。

## 实现顺序

1. 固定并检查模型文件与 tokenizer 的共同版本信息，以及明确的兼容错误。
2. 实现单条推理，再用相同采样契约扩展批量与流式接口；验证相同输入和种子下的语义一致性。
3. 用命令行建立最小本地推理接口，并用独立报告入口读取固定语料；运行时本身不读取训练数据。
4. 记录加载、未预热首请求、预热后延迟、吞吐和内存，注明设备、软件版本、输入规模、重复次数与统计方式。

性能数据只描述本教学模型在测量环境下的表现，不能推断真实大模型、GPU 或网络服务的性能。
