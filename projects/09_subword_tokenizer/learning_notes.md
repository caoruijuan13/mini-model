# 09 学习笔记

先手算 `abab`：字符 ID 序列 `[a, b, a, b]` 中 `(a,b)` 出现两次，先合并为 `[ab, ab]`。若允许频数为 1 的第二轮，则 `(ab,ab)` 合并为 `[abab]`。记录的规则顺序为 `a+b→ab`、`ab+ab→abab`；编码新文本 `ababab` 时依序应用，得到 `[abab, ab]`。

不要把三件事混为一谈：

1. **学习 merge：**在训练文本上统计频数，决定哪些 pair 进入规则表；
2. **编码：**在新文本上应用已保存的规则，不再修改它；
3. **训练语言模型：**模型把编码得到的 ID 当输入，另有 loss、梯度和优化器。BPE 自身没有 `backward()`。

三个纯函数、tokenizer 状态与持久化现已通过阶段测试。遇到未知字符时分别检查 `use_unk` 与 `error`：前者让编码继续，但不保证原文可逆；后者将未知字符作为错误交给调用方处理。标点、中英文和代码片段都应用同一套规则，不预设“词”一定以空格分隔。实际语料的验证/测试切分含有训练未见字符，因此 token 数下降不等于无损压缩。

这也解释了为什么真实语言模型的 token 数既不等于字符数，也不等于按空格分出的词数：token 边界由 tokenizer 的词表和规则决定，常见字符片段可能合并，罕见内容可能拆成多个单位。这里只验证了本项目的小型字符初始化 BPE，不能据此推断某个真实模型的具体分词结果。
